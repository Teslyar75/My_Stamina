## Диагноз (установлен чтением кода, не догадка)

1. **Два профиля.** Первый проход — `orion-recon` (`tools: bash/edit/write/task/todowrite/pencil/mcp = false`,
   `.opencode/agents/orion-recon.md:4–11`). Второй проход после «ВЫПОЛНИТЬ» — `orion-commander`
   (без `tools:` → полный набор). Соответствие задано в `stamina/orion.py:63–67`.
2. **Ключевая поломка.** Второй проход запускается с новым `--agent`, но со **старым** `--session`
   от первого прохода: `stamina/orion_screen.py:929` (`session = orion.last_session(rec["id"])`),
   передача — `stamina/orion.py:512–513`, хранилище держит **одну** сессию на агента
   (`stamina/orion.py:273–298`, поле `session` в `orion/<id>.json`). Сессия OpenCode принадлежит
   агенту, поэтому смена `--agent` на живой сессии, скорее всего, игнорируется — агент остаётся
   `orion-recon` без инструментов. Это и есть давний долг «кнопка ВЫПОЛНИТЬ не даёт реальных прав»
   (`_orion/tasks.md:99`).
3. **tools-ограничения не применяются.** `pencil: false` / `mcp: false` в живой сессии не
   подействовали (`_orion/tasks.md:105–106`).
4. **Внешние пути.** Чтение вне `--dir` (например `C:\Users\mi\.config\opencode\voice\say.py`)
   вызывает интерактивный запрос разрешения; `opencode run` без терминала показать его не может →
   авто-отказ. В проекте **нет** `opencode.json` с правилами `permission` (в `.opencode/` только
   `.gitignore`, `agents/`, `node_modules/`, `package.json`).
5. **Конфликт голоса.** Глобальный `~/.config/opencode/AGENTS.md` требует озвучивать ответы через
   `say.py`, но у профиля доклада нет `bash`. Корабль озвучивает ответ сам:
   `stamina/orion_screen.py:1076–1084` (`_speak`), и молчит, если агент «заговорил» сам
   (`spoke`, `stamina/orion.py:554`).
