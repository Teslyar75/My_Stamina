# Star Typing — браузерная версия: план и промпты для Cursor

> **Паритет с десктопом (пробелы после MVP):** см. [`PARITY_PLAN.md`](./PARITY_PLAN.md) — эпики P1–P8.

## 1. Стек
- **Фронтенд:** TypeScript + React + Vite, Zustand (состояние), i18next (переиспользуем словари `stamina/i18n` → JSON).
- **Бэкенд:** Python FastAPI. Переносим логику из `stamina/` почти без изменений: `english/vocab.py`, `sm2.py`, `progress.py`, `textutil.py`, `library.py`, `pdf_import.py`, `langdetect.py`, `book_catalog.py`, `bilinguis_catalog.py`.
- **БД:** SQLite на старте (один файл), Postgres для продакшена (SQLAlchemy + Alembic, одна схема).
- **Авторизация пилотов:** логин + PIN/пароль, JWT в httpOnly-cookie; гостевой режим с localStorage.

## 3. Узкие места сейчас и как их убрать в веб-версии
Найдено при чтении кода (только чтение, код не менялся):

1. **Перевод хранится целым файлом без выравнивания с оригиналом.** `library.py` → `add_bilingual()/mark_bilingual()` пишут `original.txt` и `translation.txt` целиком; связи «абзац/предложение оригинала ↔ перевода» нет. Поэтому в режиме [2 языка] строки расползаются, а при переходе к [экран] позицию в переводе невозможно найти точно.
   **Решение:** при импорте сразу сегментировать текст на абзацы → предложения и хранить **выровненные пары** в БД: `segments(text_id, idx, para_idx, original, translation, status)`. Выравнивание: по абзацам, затем по предложениям (длина + число/имена, алгоритм Gale–Church или `bertalign` на сервере). Несопоставленное помечать `status=unaligned`, а не терять.
2. **Сегментация и пагинация на регулярках внутри огромного UI-модуля.** `speedread/book_reader.py` (≈2 100 строк): `_SENT_SPLIT` разбивает по `.!?…`, а абзацы и строки (`zip(paras, para_origins)`, `u["lines"]`, `u["offs"]`) пересчитываются в Tkinter при каждой смене режима/размера. Разные модули (`textmap.py`, `library.py::split_paragraph_words`, `book_reader.py`) режут текст по-своему → смещения не совпадают между режимами набор/чтение/экран.
   **Решение:** **одна модель данных** для оригинала, набора и перевода: `Text → Paragraph → Sentence → Token` с глобальными смещениями символов, считается один раз на сервере. Все режимы (набор, читалка, 2 языка, экран) — только разные представления этой модели; позиция = `sentence_id`, а не номер строки.
3. **Онлайн-перевод UPLINK привязан к UI-потоку набора.** `bridge.py` (стр. ~575–655) запрашивает перевод сегмента во время набора, кэширует в памяти/файле, при отсутствии сети показывает заглушку; интерфейс перерисовывается целиком через `uplink.set(...)`.
   **Решение:** переводить **заранее и по абзацам** в фоновой задаче на сервере (очередь, батчи), кэш в таблице `translations(hash, src_lang, dst_lang, text)`; фронт получает готовое через `GET /api/texts/{id}/segments?from=&to=` порциями, перевод недостающего — асинхронно с плейсхолдером, без блокировки набора.

Дополнительно: глобальные `.after()`-циклы анимации и TTS в одном потоке Tk конкурируют с набором — в вебе анимация уходит в отдельный canvas/воркер.

### Советы по режиму [2 языка] и [экран]
- Отображение — **CSS grid** `grid-template-columns: 1fr 1fr`; каждая строка сетки = одна пара предложений/абзацев, поэтому левая и правая колонки всегда на одном уровне (высота строки = максимум из двух).
- Синхронный скролл бесплатно (одна сетка); если колонки раздельные — синхронизация по `sentence_id` через IntersectionObserver.
- Переход [2 языка] → [экран]: передаём текущий `sentence_id`, экранный режим открывает страницу, содержащую его. Никакого пересчёта текста — только перерасчёт раскладки.
- Длинные книги: виртуализация (`react-virtuoso`), подгрузка сегментов окнами по 200.
- Подсветка текущего предложения в обеих колонках; клик по предложению = озвучить/показать пару.

## 5. Промпты для Cursor (копировать по одному)

**Промпт 1 — Каркас.**
> В репозитории `My_New_Stamina` создай папку **`web_star_typing/`** с `frontend/` (Vite + React + TypeScript, ESLint, Vitest) и `backend/` (FastAPI, SQLAlchemy 2, Alembic, pytest, SQLite по умолчанию, Postgres через `DATABASE_URL`). Добавь `packages/themes/` (JSON скинов, см. `docs/skins/SKINS.md`) и `docker-compose.yml` (backend, frontend, postgres). Python-код из `stamina/` не трогай — бэкенд импортирует его как пакет из корня монорепо. Критерии: `npm run dev` показывает страницу «Star Typing Web»; `GET /api/health` → `{"ok":true}`; тесты зелёные; README в `web_star_typing/`. Позже папку выносят в отдельный GitHub-репозиторий.

**Промпт 2 — Единая модель текста.**
> В `web_star_typing/backend` реализуй модели `Text, Paragraph, Sentence, Segment(original, translation, status)` с глобальными смещениями символов и Alembic-миграцию. Сервис `segment_text(text, lang)` — один источник правды для разбиения (абзацы: пустая строка/отступ; склеивать жёсткие переносы внутри абзаца; предложения: учитывать сокращения Mr., e.g., многоточия, прямую речь). Импорт: `POST /api/texts` (txt/pdf через `stamina/pdf_import.py`), `POST /api/texts/bilingual` (оригинал + перевод) с выравниванием абзац→предложения (Gale–Church по длине). Критерии: юнит-тесты на 10 сложных случаев разбиения; для пары глав из `bilinguis` ≥90% предложений выровнены; невыровненные помечены `unaligned`; `GET /api/texts/{id}/segments?offset&limit` отдаёт пары.

**Промпт 3 — Тренажёр набора.**
> Сделай во `frontend` экран набора по образцу `stamina/bridge.py` и `hud.py`: текст из `/segments`, ввод через скрытый input, посимвольная подсветка (верно/ошибка/курсор), скорость, точность, таймер, раскладки из `stamina/layouts.py` (портируй в TS). Критерии: 60 fps на тексте 100 000 символов (виртуализация), нет задержки ввода >16 мс, статистика сохраняется `POST /api/sessions`.

**Промпт 4 — Пилоты и авторизация.**
> Реализуй пилотов: регистрация/вход (имя + PIN/пароль, bcrypt), JWT в httpOnly-cookie, аватары, прогресс, Доска почёта (логика из `pilots.py`, `pilot_stats.py`, `missions.py`). Импорт старых данных пилота из JSON (`pilot_migrate.py`). Критерии: два пилота не видят данные друг друга; e2e-тест Playwright вход→сессия→доска почёта.

**Промпт 5 — [2 языка], [экран], читалка, фоновый перевод.**
> Режим [2 языка]: CSS grid, каждая строка = пара сегментов, подсветка текущего предложения в обеих колонках, клик = озвучка. Режим [экран]: постраничная раскладка 1/2 страницы (как Readest), позиция передаётся по `sentence_id` при переключении режимов. Фоновый перевод: очередь задач на бэкенде переводит недостающие сегменты по абзацам батчами, кэш в таблице `translations` по хешу; фронт показывает плейсхолдер «перевод загружается» и не блокирует набор. Критерии: переключение 2 языка↔экран↔набор сохраняет точное предложение; колонки не расходятся по высоте на 3 тестовых книгах; без сети показываются кэшированные переводы.

**Промпт 6 — АНГЛИЙСКИЙ.**
> Перенеси отсек английского (`stamina/english/*`): наборы слов, карточки, склад (`warehouse.py`), SM-2, прогресс/XP/ранги, TTS через `speechSynthesis` с индикатором «ЧИТАЕТ…», проверку произношения через `vosk-browser` (WASM, модель en-small, кэш в IndexedDB) с индикатором «СЛУШАЮ…» и уровнем микрофона, процент совпадения и подсветка слов по алгоритму из `textutil.py` (портировать с тестами на тех же примерах). Критерии: проценты совпадают с Python-версией на 20 тестовых парах; работает в Chrome и Edge; словарь грузится из API.

**Промпт 7 — Скорочтение.**
> Перенеси `stamina/speedread`: RSVP (ORP-подсветка, WPM), таблицы Шульте, викторины. Тайминг — `requestAnimationFrame`, погрешность < 5 мс. Критерии: тесты таймера, сохранение результатов в API.

**Промпт 8 — Живой космос, темы, звуки, радио.**
> Живой космос из `living_space.py` → Canvas/PixiJS слой за интерфейсом, пауза при `document.hidden`, настройка «меньше анимации» (`prefers-reduced-motion`). Темы через CSS-переменные из `web_star_typing/packages/themes/*.json` (формат `docs/skins/SKINS.md`). Звуки — Web Audio. Радио — по `docs/radio/CURSOR_TASK_RADIO.md`, фон через Media Session API. Критерии: CPU фона < 10% на ноутбуке; смена темы без перезагрузки.

**Промпт 9 — i18n, PWA, деплой.**
> Конвертируй `stamina/i18n` в JSON для i18next (ru/uk/en/de), переключатель языка. PWA (manifest, service worker, офлайн-кэш словаря и текстов). Docker-деплой с Postgres, HTTPS (Caddy). Критерии: Lighthouse PWA ≥ 90; все строки интерфейса переведены; `docker compose up` поднимает всё.
