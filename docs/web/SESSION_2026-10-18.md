# Сессия 2026-10-18 — единые хоткеи Home/PgUp/PgDn, Esc/Del и очистка старых вариантов

## Цель сессии

Завершить работу, начатую в Cursor: сделать **один стандарт горячих клавиш** для десктопа и веба,
убрать старые варианты (`F8`, `F11`, `=`) и не сломать при этом локальную навигацию в читалках,
списках и полях ввода. Затем — проверить, почистить мусор и отправить оба репозитория на GitHub.

## Принятый стандарт

| Клавиша | Действие |
| --- | --- |
| `Home` | Орион (вызов гида) |
| `PgUp` (`Prior`) | слайдшоу в простое |
| `PgDn` (`Next`) | полный экран; выход — `Esc`/`Del` или кнопка «✕ ЭКРАН» |
| `Esc` / `Del` | пауза / продолжить; выход из полного экрана |

**Без `Ctrl`/`Alt`/`Shift`.** Причина: Chrome резервирует `Ctrl+PgUp`/`Ctrl+PgDn` под переключение
вкладок, и в вебе такие сочетания ненадёжны.

**Главный принцип:** хоткей кабины срабатывает только там, где клавиша ещё не занята локальным
экраном. Если читалка/список/поле ввода обрабатывает `Home`/`PgUp`/`PgDn` — приоритет у них,
поведение не меняется.

## Хвосты и что учитывать дальше

1. **Орион на десктопе — заглушка.** `_call_orion()` только пишет статус «голосовой вызов пока на
   веб-версии (Home)». Реальный Орион живёт в вебе.
2. **Этот коммит десктопа не в `master`.** Ранее PR #26 влил `feat/ship-slideshow` в `master`
   (956b52b), но новый `7d069f6` появился уже после. Если нужен `master` — открыть/обновить PR.
3. **`master` веба отстаёт** (origin на 45db64d, PR #16); пушить локальный `master` не нужно.
4. **Читалки — исключение из `GLOBAL_KEYS`.** В справке написано `PgDn — экран`, но в книжной
   читалке `PgDn` листает страницу, а экран — `F11`/кнопка. Это осознанно: «не трогать функционал
   в другом месте».
5. **В i18n остались неиспользуемые ключи** (в т.ч. старые `F11`/`Esc`-подписи), ~63–65 на язык.
   `i18n_check.py` показывает их как «лишние», но exit code 0. Чистить — отдельной задачей.
6. **CRLF.** JSON-файлы i18n должны сохранять CRLF и финальный перевод строки, иначе git показывает
   дифф всего файла. Правки делались текстовой заменой, без `json.dump`.

## Технические заметки на будущее

- **Ключ i18n — это русская исходная строка.** При смене текста в коде нужно менять и ключ во всех
  четырёх файлах (`ru/uk/en/de`), а не только значение. Иначе перевод «не находится».
- **`bind_all` + локальный обработчик = двойное срабатывание.** Поэтому `_on_key()` возвращает
  `break`, а для английской зоны стоит явная проверка в `_chrome_hotkey()`.
- **Windows-консоль в cp1251** не печатает кириллицу/символы (`▶`, `⛶`, `→`). Для проверок писать
  вывод в файл или пользоваться `read`/`grep`, а не `print` в терминал.
- **Проверка i18n:** `python tools/i18n_check.py` (при необходимости `--fix-ru`).
- **Веб-сборка:** `cd web_star_typing/frontend && npm run build`; тесты — `npm test -- --run`.
