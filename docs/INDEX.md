## Что предлагаю сделать с документами дальше

Раньше правило было «переименовать и разложить». Проверил ссылки: почти на каждый
документ кто-то ссылается, поэтому слепой `git mv` ломает навигацию сразу в 30 местах.
Поэтому предлагаю по шагам:

1. **Сделано:** этот индекс — единая точка входа.
2. **Дальше:** устаревшие («история») переносить в `docs/archive/2026-10/`
   **вместе с правкой ссылок** в тех же коммитах, по 5 файлов за раз.
3. **Имена.** Предлагаю схему `ТЕМА_ВИД_ДАТА.md`:
   - `ORION_BOARD.md` → `orion-board.md` (доска, живой документ — без даты);
   - `HANG_100_CPU_2026-10-20.md` → `incident-2026-10-20-hang-cpu.md`;
   - `SESSION_REPORT_2026-10-19.md` → `archive/session-2026-10-19.md`.
4. **Дубли.** Свести `PRODUCT_IDEAS.md` + `FEATURES_2026-10.md` +
   `ORION_PROPOSALS_2026-10-20.md` в один «бэклог» с тремя разделами
   (сделано / хотим / предлагаю).
5. **Удаление.** Безвозвратно не удаляем: сначала перенос в `archive/`, удаление —
   отдельной командой пилота.
