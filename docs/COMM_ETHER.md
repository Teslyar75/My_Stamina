# ЭФИР — канал связи экипажа (десктоп): что сделано и как устроено

> **Коротко.** В настольной версии появился седьмой раздел **ЭФИР** (`Ctrl+6`) — общая лента
> сообщений экипажа. Пилоты одного компьютера оставляют друг другу сообщения, непрочитанное
> подсвечивает кнопку раздела. Это **прототип** и **фундамент будущего онлайн-чата** (идея
> I-001 «эфир флота»), сделанный вне границ этапа E4-02 — по решению владельца.

## 1. Зачем

- **Проверка механизма.** Нужно было убедиться, что «пилоты переписываются» — понятная и
  нужная вещь, и что её можно собрать внутри уже работающего приложения, без сервера.
- **Фундамент онлайна.** В `docs/PRODUCT_IDEAS.md` (I-001 «эфир флота») общий канал экипажа —
  часть задуманного онлайна; в `docs/PROJECT_CONTEXT.md` он стоит в парковке **E4-02** и
  требует модерации. Поэтому слой данных сделан **по образцу будущего серверного API**: когда
  появится сервер, поменяется только начинка одного модуля, а экран — нет.
- **Десктоп — песочница.** Решение D6: на десктопе пробуем и проверяем, веб и онлайн — потом.

## 2. Как пользоваться

| Шаг | Действие |
| --- | --- |
| 1 | В шапке пульта выбрать раздел **ЭФИР** (`Ctrl+6`). |
| 2 | Прочитать ленту. Свой позывной — своим цветом, своё сообщение помечено **▸**, время — слева-снизу строки. |
| 3 | Написать в строке ввода внизу и нажать **Enter** (или **ОТПРАВИТЬ**). |
| 4 | **ОБНОВИТЬ** — перечитать ленту; **?** / **F1** — справка раздела. |
| 5 | Проверить ответ напарника: **Ctrl+Shift+P** → другой позывной → снова **Ctrl+6**. |

**Подсказки.** Если есть непрочитанные сообщения, кнопка **ЭФИР** в шапке подсвечена янтарным.
При входе в раздел сообщения сразу помечаются прочитанными, а в заголовке видно
«Сообщений: N · Новых: M». Если пилота нет (режим без экипажа), поле ввода заблокировано и
написано, что делать.

## 3. Как устроено

### 3.1 Слои

```
ЭКРАН     stamina/comm_screen.py   лента, ввод, счётчики, цвета      (Tk)
   │
   │  messages() / send() / unread() / mark_read()
   ▼
ДАННЫЕ    stamina/comm.py          общий файл экипажа, лимиты       (без Tk, тестируется)
   │
   ▼
ФАЙЛ      <корень данных>/comm.json   %APPDATA%\Stamina\comm.json
```

Экран **не знает**, откуда берутся сообщения: он видит только четыре функции. Это и есть
точка замены при переходе на сервер.

### 3.2 Файлы

| Файл | Что делает |
| --- | --- |
| `stamina/comm.py` | Слой данных: чтение/запись ленты, лимиты, «непрочитанное». Без Tk. |
| `stamina/comm_screen.py` | Экран `CommScreen(tk.Frame)`: лента, поле ввода, кнопки, счётчики. |
| `stamina/comm_hook.py` | Врезка по образцу других вкладок: `KEY`, `TITLE`, `load_class`, `create`; при сбое — запись в `comm_error.log` и работа без вкладки. |
| `stamina/nav.py` | Зона `comm` в `ZONE_ORDER` (перед `settings`) и её титул «ЭФИР». |
| `stamina/cockpit.py` | `SCREENS` (7 зон), создание экрана, подсветка непрочитанного, `on_key`, фокус в поле, маршрут `show()`. |
| `stamina/page_help.py` | Страница справки `comm`, горячая клавиша раздела, «Ctrl+1…7» в общей подсказке. |
| `stamina/screens.py` | Строка подсказок: «Ctrl+1…7 — разделы». |
| `stamina/i18n/{ru,uk,en,de}.json` | 9 новых фраз (заголовки, кнопки, подсказки, страница справки) × 4 языка. |
| `tests/test_comm.py` | Данные (8), экран (4), разметка (1), пульт (1). |

### 3.3 Формат `comm.json`

```json
{
  "version": 1,
  "messages": [
    {"id": "9f2c1ab4d7e0", "author": "<id пилота>", "callsign": "Комета",
     "ts": 1776500000.5, "text": "Привет, экипаж!"}
  ],
  "read": {"<id пилота>": 1776500000.5}
}
```

- `messages` — старые → новые; `read` — время последнего прочтения по каждому пилоту.
- Файл **общий**, лежит в корне данных экипажа, а не в папке пилота: канал один для всех.

### 3.4 Слой данных `stamina/comm.py`

| Функция | Поведение |
| --- | --- |
| `path()` | Путь к `comm.json` (корень данных берётся в момент вызова — так тесты подменяют его). |
| `load()` | Читает ленту. Нет файла, битый JSON, не тот тип — возвращает **пустую ленту**, без исключений. |
| `messages()` | Список сообщений (старые → новые). |
| `send(author, callsign, text, ts=None)` | Добавляет сообщение: убирает переносы и лишние пробелы, режет до 500 знаков, ставит `id` (uuid) и время; пустое — отбрасывает (`None`); своё сообщение сразу помечает прочитанным; держит не больше 500 последних. |
| `unread(pid)` | Сколько сообщений пилот не видел: только чужие и новее отметки прочтения. |
| `mark_read(pid, ts=None)` | Отмечает прочитанным (по умолчанию — до последнего сообщения); назад не откатывает. |

Запись **атомарная**: сначала `comm.json.tmp`, затем замена — файл не бьётся, если приложение
закрыли в момент записи.

### 3.5 Экран `stamina/comm_screen.py`

Сверху вниз: заголовок «ЭФИР — СВЯЗЬ ЭКИПАЖА» со счётчиками, кнопки **ОБНОВИТЬ** и **?**,
панель **ОБЩИЙ КАНАЛ** с лентой, внизу — строка ввода и **ОТПРАВИТЬ**.

| Что | Как |
| --- | --- |
| Лента | `tk.Text` только для чтения, перенос по словам, прокрутка колесом (Windows/macOS — `<MouseWheel>`, Linux — кнопки 4/5). |
| Позывные | Цвет «акцента» пилота из реестра экипажа (cyan / amber / green / red / purple). |
| Своё сообщение | Метка **▸** и обычный цвет позывного. |
| Цвета | Берутся **у текущего скина в момент отрисовки** (`theme.*`), потому что цвета тегов `tk.Text` смена скина не перекрашивает. |
| Обновление | `refresh()`: перечитать ленту → отрисовать → отметить прочитанным → обновить счётчики и подсветку кнопки раздела. |
| Фокус | При входе в раздел фокус сразу в поле ввода — можно печатать. |
| Без пилота | Поле ввода заблокировано, в ленте — подсказка. |
| Справка | `page_help_key()` → страница `comm` (F1 и кнопка «?»). |

### 3.6 Врезка в пульт

- Зон стало **семь**: Мостик, Английский, Скорочтение, Отдых, Радиорубка, **Эфир**, Настройки;
  «Эфир» — не подменю Мостика, потому что это самостоятельный канал связи всего экипажа.
  «Настройки» остались последними.
- Экран подключается через `comm_hook` (как остальные вкладки): если что-то сломалось при
  импорте или создании — пульт работает без раздела, причина пишется в `comm_error.log`.
- Непрочитанное: `update_comm_badge()` красит кнопку раздела янтарным, при входе — снимает подсветку.

### 3.7 Переводы

9 новых фраз (заголовок, «ОБЩИЙ КАНАЛ», «ОТПРАВИТЬ», счётчики, две подсказки, страница справки,
строка горячей клавиши) добавлены во все четыре словаря: **русский, українська, English, Deutsch**.
Правка — **текстовой заменой** (не `json.dump`), кодировка UTF-8, переводы строк **CRLF** и
финальный перевод строки сохранены. Проверка — `python tools/i18n_check.py` → **exit 0**.

## 4. Принятые решения и почему

| Решение | Почему так |
| --- | --- |
| Отдельная **зона**, а не подменю Мостика | Эфир — канал всего экипажа; подменю Мостика («Миссии, Свой текст, Бортжурнал, Настройки мостика») — про тренировку. |
| Данные — **общий файл**, а не в папке пилота | Смысл в общении между пилотами; в папке пилота каждый видел бы только себя. |
| API как у **будущего сервера** | При онлайне меняется начинка `comm.py`; экран, справка и тесты экрана остаются. |
| **Без Tk** в слое данных | Логику проверяют обычные тесты, без окна; слой не зависит от интерфейса. |
| Лимиты 500 знаков / 500 сообщений | Защита от случайной вставки простыни и от безграничного роста файла. |
| Своё сообщение сразу «прочитано» | Иначе после отправки бейдж показывал бы непрочитанное у себя же. |
| Цвета — **токены скина** | Требование проекта: никаких жёстких цветов; в скинах (например «Старая Англия») эфир выглядит «в теме». |
| Подсветка кнопки, а не цифра в подписи | Ширина кнопки в шапке измеряется при создании: цифра «(3)» вылезала бы за край; цвет — безопасно. |

## 5. Границы и ограничения (сейчас)

- **Локально.** Сообщения живут на одном компьютере, между профилями пилотов. Напарник за
  другим компьютером их **не увидит** — для этого нужен сервер (раздел 8).
- **Одна общая лента.** Нет личных каналов, тредов, ответов-цитат, реакций, вложений, поиска.
- **Без правки и удаления** сообщений — их всё равно придётся делать вместе с модерацией.
- **Обновление вручную**: лента перечитывается при входе в раздел, кнопкой «ОБНОВИТЬ» и после
  отправки. Живого потока (когда писал другой в другой вкладке) нет — это уже про сервер.
- **Лимит истории** 500 сообщений: старое вытесняется новым.

## 6. Найденный и исправленный дефект: строка ввода уезжала за край

**Как проявился.** Владелец написал: «не вижу окна для ввода ответа».

**Причина.** Панель ленты упаковывалась **раньше** строки ввода и с `expand=True` забирала
всё свободное место; строке ввода (последней в очереди) не оставалось ничего. Дополнительно
`tk.Text` без `height` запрашивал 24 строки — то есть ещё больше места.

**Измерение (до / после)**

| Окно | content | строка: высота / видна | поле: высота / видно |
| --- | --- | --- | --- |
| 1280×800, до | 644 | 1 / **нет** | 1 / **нет** |
| 900×560, до | 638 | 1 / **нет** | 1 / **нет** |
| 1280×800, после | 644 | 51 / да | 49 / да |
| 900×560, после | 638 | 51 / да | 49 / да |

**Исправление.** Строка ввода теперь пакуется **к низу и до ленты** (`side=tk.BOTTOM`), а у
ленты ограничен запрошенный размер (`height=6`) — она больше не вытесняет ввод.

**Тест-страж.** `tests/test_comm.py::CommLayoutTest.test_input_row_is_visible` — на прежней
разметке падает («поле ввода не показано»), на новой проходит. Проверено обоими состояниями.

## 8. Что дальше: путь к онлайн-эфиру

Ничего из этого не входит в текущую работу — это карта, чтобы не переделывать дважды.

**Что меняется в коде.** Только начинка `stamina/comm.py`: те же четыре функции начинают
ходить по сети. `comm_screen.py`, справка, тесты экрана — не меняются. Добавится состояние
«нет связи» и повтор отправки.

**Что должен уметь сервер (контракт-набросок)**

| Запрос | Зачем |
| --- | --- |
| `GET /comm?since=<время>` | Новые сообщения после отметки (лента и счётчик «Новых»). |
| `POST /comm` | Отправить сообщение (текст, время клиента, `id` для защиты от дублей). |
| `POST /comm/read` | Отметить прочитанным до времени. |
| `GET /comm/presence` | Кто в эфире (позже; вместе с «Орионом»). |

**Что потребуется кроме самого сервера:** авторство по пилоту (токен), один канал на экипаж,
пагинация истории, модерация и правила (E4-02 требует модератора), приватность и хранение
персональных данных, оффлайн-очередь отправки.

**Полезные мелочи в первую очередь:** ответ-цитата, «кто сейчас на борту», уведомление вне
раздела, живые сообщения без кнопки «ОБНОВИТЬ».

## 9. Что осознанно не сделано

- Модерация, жалобы, блокировки — без них онлайн не запускать, а локально нечего модерировать.
- Приватные каналы, ответы-цитаты, реакции, вложения, поиск по истории.
- Правка и удаление своих сообщений.
- Многокомпьютерная синхронизация (это и есть сервер).
- Шифрование (пока данные локальные).
- Пагинация длинной истории (сейчас 500 последних).
