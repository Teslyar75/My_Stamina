## 1. Защита от зависаний и потери работы

### 1.1. Автоматические резервные копии данных пилота — P0
**Зачем:** откат кода стоил бы только времени, а откат данных — это потерянные
книги, прогресс, миссии. Сегодня в `%APPDATA%\Stamina` нет ни одной копии.
**Что сделать:** при запуске (раз в сутки) копировать `app.json`, `pilots.json`,
`owner.json`, `library.json`, `speedread.json`, `english.json` и папку `orion/`
в `%APPDATA%\Stamina\backups\YYYY-MM-DD\`, хранить 7 последних, старое чистить.
Добавить в «Настройки» кнопку «ВОССТАНОВИТЬ ИЗ КОПИИ».
**Как проверить:** удалить пробный `settings.json` → восстановление возвращает файл.

### 1.2. Режим «безопасный запуск» — P0
**Зачем:** когда окно не отвечает, нужен способ дойти до настроек, ничего не удаляя.
**Что сделать:** запуск с ключом `--safe` (и пункт в ярлыке): не собирать тяжёлые
отсеки, не запускать анимации, не проверять обновления. Кабина и «Настройки» работают
всегда.
**Как проверить:** окно открывается за <1 с на профиле с большой книгой.

### 1.3. Бюджет старта с записью в журнал — P1
**Зачем:** «окно не отвечает» превращается в «какой экран сколько строил».
**Что сделать:** при старте мерить `process_time` на каждый отсек и писать строку
в `start.log`: `bridge 0.31 c`, `english 0.44 c`, итог. Если отсек дольше 0.3 с —
писать предупреждение.
**Как проверить:** в журнале есть разбивка по отсекам, итог < 1 с.

### 1.4. Дымовой тест запуска в CI — P1
**Зачем:** зависание ловится только запуском. Тесты его не видели.
**Что сделать:** тест, который строит кабину с тестовым профилем, крутит mainloop
3 секунды, считает `process_time` и падает, если CPU > 60 % или появилось
замирание > 1.5 с (читаем `stall.log`).
**Как проверить:** искусственно вернуть старую ошибку (`grid` всех экранов) — тест
краснеет.

### 1.5. Ротация журналов — P2
**Зачем:** `start.log` и `stall.log` растут без предела и сами станут тормозом.
**Что сделать:** обрезать по 512 КБ, хранить один архивный хвост.

## 2. Дисциплина разработки (в первую очередь для агентов)

### 2.1. Одна ветка на агента — P0
**Зачем:** два агента в одном рабочем дереве дважды за ночь затёрли друг друга;
`reset --hard` снёс готовые коммиты.
**Что сделать:** правило в `AGENTS.md`: работать в ветке `agent/<имя>/<тема>`,
в `master` — только через слияние после зелёных тестов. `reset --hard` и
`push --force` — только по прямой команде пилота.
**Как проверить:** в `git log --first-parent master` видны только слияния.

### 2.2. Тег перед рискованной правкой — P1
**Зачем:** `git checkout` старый коммит всегда под рукой.
**Что сделать:** скрипт `tools/snapshot.ps1` — создаёт тег `snap-YYYYMMDD-HHMM`
и печатает одну строку «откат: git checkout <тег>».
**Как проверить:** тег появляется в `git tag --sort=-creatordate | head -1`.

### 2.3. Единый список того, что агент сделал — P1
**Зачем:** вчера я не знал, что параллельно идёт вторая правка.
**Что сделать:** `.opencode/agents/ACTIVE.md` — кто, что, какие файлы держит.
Перед правкой агент дописывает строку, после — убирает.
**Как проверить:** файл существует и в нём есть текущая запись.

**Как проверить:** на книге с известными склейками находит их и не портит
соседние слова (`ивот` не внутри `живот`).

## 4. Мостик и библиотека

### 4.1. Поиск по книге — P1
**Зачем:** в книге на 103 000 слов найти место без поиска невозможно.
**Что сделать:** `Ctrl+F` в редакторе: подсветка всех совпадений, счётчик,
переход по `Enter`, «найти далее».
**Как проверить:** 3 совпадения → счётчик «1 из 3».

### 4.2. Закладки и оглавление — P1
**Зачем:** длинный текст теряет место при переключении отсеков.
**Что сделать:** закладка `Ctrl+B`, список закладок в боковой панели,
переход по главам (строки, начинающиеся с `ГЛАВА`/`CHAPTER`).

### 4.3. Прогресс по тексту — P2
Полоса «набрано 3377 из 103 000 слов» и оценка времени по текущей скорости.

## 8. Обновления

### 8.1. Проверка обновлений в фоне с таймаутом — P1
**Зачем:** `updater.py` умеет `timeout=120` на скачивание; если запустить это в
главном потоке — окно встанет на две минуты.
**Что сделать:** аудит: любой сетевой вызов только в потоке, `after(0, …)` для
обновления интерфейса; таймаут проверки — 10 с, загрузки — 60 с с прогрессом.

### 8.2. Откат обновления — P2
Хранить предыдущую версию рядом: «Вернуться к 3.6.9» в «Настройках».
