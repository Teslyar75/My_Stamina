# Приём ИИ-агента на борт: что готово, что нужно сделать, какие права

Документ отвечает на четыре вопроса:

1. **Что на корабле уже готово** принять агента (заселить, поселить, разговаривать).
2. **Что нужно сделать**, чтобы агент реально вошёл на борт и работал.
3. **Что уже есть внутри** для взаимодействия агента с пилотом.
4. **Какие права** у агента на борту сейчас.

> **Снимок на 18.10.2026, сверено с кодом:** `stamina/orion.py`, `stamina/owner_key.py`,
> `stamina/orion_screen.py`, `stamina/voice/`, `stamina/orion_hook.py`, `stamina/cockpit.py`,
> `.opencode/agents/*.md`.
> Замысел заселения и очередь работ — [DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md), раздел 11.
> Решения о границах — [PROJECT_CONTEXT.md](PROJECT_CONTEXT.md), решения **D16** (агент и ключи снаружи),
> **D17** (права выдаются на входе, Командир — по коду владельца), **D18** (манеры — документ борта)
> и **D6** (десктоп офлайн-first).

**Коротко:** **принять агента корабль уже умеет** — посадить в реестр, выдать права на входе,
написать ему манеры документом, разговаривать, озвучивать, спрашивать разрешение и записывать
задания. Сценарий заселения: пилот выбирает профиль → окно 选 ИИ-агента → вход на борт.
Командир может сменить агента или заселить нового; обычный игрок — по уровню доступа;
если агента нет — возможность приобрести или вход без ИИ-агента (标准 Орион).

**Права и манеры — разные вещи.** Права агент получает **на входе** (уровень доступа; Командир —
только по коду владельца корабля) и **на борту их не меняют**. Манеры — это документ корабля:
поведение агента пилот пишет сам и правит когда угодно.

## 1. Что уже готово к приёму агента

### 1.1. Ядро: место на борту, память, задания — `stamina/orion.py`

| Система корабля | Что делает | Где живёт (данные) |
| --- | --- | --- |
| **Реестр пассажиров** | Список агентов борта, активный агент, поля записи | `%APPDATA%\Stamina\agents.json` |
| **Память диалога** | Реплики `pilot / orion / system`, сессия OpenCode | `%APPDATA%\Stamina\orion\<id>.json` |
| **Документ манер** | Поведение агента, которое пишет пилот; уезжает агенту блоком `[МАНЕРЫ АГЕНТА]` | `%APPDATA%\Stamina\orion\<id>.character.md` |
| **Документ заданий** | Задания пилота агенту со статусами `open / done` | `%APPDATA%\Stamina\orion_tasks.json` |
| **Код владельца** | Единственный способ выдать права Командира (солёный хэш PBKDF2, не текст) | `%APPDATA%\Stamina\owner.json` |

Запись агента (поля) — `upsert()`:

```text
id, name, kind ("opencode"), access (commander|observer|crew), profile, model,
voice (ship|agent|off), enabled, note, created
```

Дополнительно уже работает:

- **атомарная запись** JSON (временный файл + замена) — данные не бьются при закрытии;
- **лимиты**: до 200 реплик в памяти диалога, до 6000 знаков в реплике, задание — до 6000 знаков,
  документ манер — до 4000 знаков;
- **документ манер создаётся сам** при входе агента на борт (`ensure_character` → заготовка с именем
  агента), уходит с ним при высадке и передаётся агенту перед каждой репликой (`character_block`);
- **код владельца** (`stamina/owner_key.py`): задаётся один раз, хранится только хэшем, проверяется
  с блокировкой после пяти ошибок подряд;
- **бортовой Орион нельзя высадить** (`remove()` отказывает для `id = "orion"`) — только отключить,
  чтобы корабль не остался без разума;
- **переключение активного пассажира**, включение/выключение агента;
- **разбор речи пилота** `detect_task()` / `is_yes()` / `is_no()` — по словам («запиши», «на заметку»,
  «да» / «нет») без Enter, что даёт двухшаговый поток записи задания.

### 1.2. Запуск агента: подключение к движку

- **Поиск движка** — `find_cli()`, порядок проверки:
  1. переменная среды `STAR_TYPING_OPENCODE` (путь, заданный вручную — берётся как есть);
  2. `opencode` в `PATH`;
  3. `opencode.cmd` в `PATH`;
  4. `%APPDATA%\npm\node_modules\opencode-ai\bin\opencode.exe`;
  5. `%APPDATA%\npm\opencode.cmd`.
- **Обёртка .cmd заменяется настоящим exe** (`_native_exe`): рядом с npm-обёрткой ищется
  `node_modules/opencode-ai/bin/opencode.exe`. Это не косметика: `cmd.exe` **обрезает аргумент
  на первом переводе строки**, а запрос к агенту многострочный. Если настоящего exe рядом нет,
  корабль схлопывает запрос в одну строку (`flatten`) — ничего не теряется.
- **Готовность борта** — `available()` → `(готово, путь к движку)`.
- **Команда запуска** — `opencode run --format json --dir <папка корабля> [--session …] [--agent …] [--model …] <запрос>`.
- **Ответ агента** — `run_profile()`: таймаут 600 с, разбор потока JSON-событий (`parse_events`),
  извлечение текста ответа, `sessionID`, списка вызванных инструментов, признака отказа (`denied`)
  и признака «агент озвучил себя сам» (`spoke`).
- **Продолжение диалога** — через `--session`, чтобы агент помнил разговор.

Проверено на этой машине (пример): движок найден — `%APPDATA%\npm\opencode.CMD`,
он же превращается в `%APPDATA%\npm\node_modules\opencode-ai\bin\opencode.exe`.

### 1.3. Голос корабля — `stamina/voice/`

| Модуль | Умение |
| --- | --- |
| `mic.py` (`MicControl`) | Кнопка «ГОЛОС» в интерфейсе: включает/выключает слух, показывает состояние и уровень |
| `stt.py` (`Listener`) | Слух: 16 кГц, блок 4000 сэмплов, порог RMS, склейка фразы по паузе; ищет модель в `models/` |
| `tts.py` (`speak`) | Голос корабля: озвучка ответа агента через `say.ps1` (голоса Windows), обрезка текста до лимита |
| `say.ps1` | Собственно озвучка (ASCII-only, чтобы PowerShell не ломал кириллицу) |

**Режимы голоса** у пассажира (`voice`):

- `ship` — **корабль озвучивает** ответ агента (по умолчанию; агент без shell сам говорить не может);
- `agent` — агент озвучивает себя сам (корабль молчит, если увидел вызов `say.py`);
- `off` — без озвучки.

### 1.4. Интерфейс: зона «ОРИОН» — `stamina/orion_screen.py`

- Зона **ОРИОН** — седьмая из восьми: **Ctrl+7** (последняя — Настройки, Ctrl+8).
- Кнопка **ОРИОН** и клавиша **Home** открывают зону и **сразу включают микрофон** (`_call_orion` → `listen()`).
- Подвкладки: **ЧАТ** и **АГЕНТЫ**.
- Зона подключается мягко: если модуль упал при импорте, корабль работает без вкладки,
  причина — в `%APPDATA%\Stamina\orion_error.log` (`orion_hook.py`).

**Вкладка ЧАТ:**

- **Живая линия** — последняя реплика пилота и ответ агента (доска по умолчанию скрыта);
- кнопки **ДОСКА** (вся переписка), **ОЗВУЧКА: ВКЛ/ВЫКЛ**, **СМЕНИТЬ** (пассажира), **ОЧИСТИТЬ**;
- поле ввода + кнопка **ГОЛОС** + **ОТПРАВИТЬ**;
- строка **«Записать задание в документ?»** с кнопками **ДА, ЗАПИСАТЬ / НЕТ**;
- строка **разрешения** с кнопками **✔ ВЫПОЛНИТЬ / ОТМЕНА** (появляется, когда агент просит добро).

**Вкладка АГЕНТЫ:**

- **ПАССАЖИРЫ БОРТА** — список заселённых агентов + **＋ ЗАСЕЛИТЬ НОВОГО**;
- **КАРТОЧКА ПАССАЖИРА** — ИМЯ, МОДЕЛЬ, ЗАМЕТКА, **ПРАВА НА ВХОДЕ** (три кнопки: ЭКИПАЖ /
  НАБЛЮДАТЕЛЬ / КОМАНДИР), ГОЛОС, вкл/выкл;
- **права — только при заселении нового**: у пассажира, который уже на борту, кнопки закрыты,
  а подсказка объясняет, что права выдаёт владелец корабля на входе;
- **КОМАНДИР** открывает окно **КОД ВЛАДЕЛЬЦА**: если кода ещё нет — пилот задаёт его здесь
  (два ввода) и становится владельцем; неверный код — права не выдаются;
- **МАНЕРЫ АГЕНТА** — редактор документа поведения (Text с прокруткой) + **СОХРАНИТЬ МАНЕРЫ**;
  подсказка показывает полный путь к файлу документа;
- кнопки **СОХРАНИТЬ / СДЕЛАТЬ АКТИВНЫМ / УБРАТЬ С БОРТА**.

Если движок не найден, доска честно пишет: «OpenCode не найден: Орион на связи не будет».

### 1.5. Что агент знает о корабле и о пилоте

Перед каждым сообщением корабль добавляет отметку `[КОРАБЛЬ]` (`context_line`):

```text
[КОРАБЛЬ] открыт раздел «Миссии» · подвкладка «…» · перед этим пилот был в разделе «Мостик» ·
пилот: <позывной> · уровень доступа: <…> · версия корабля <…> · окно <…>
```

Поэтому агент понимает «здесь», «тут», «в этом окне» — и знает, откуда пилота позвали.

Перед отметкой `[КОРАБЛЬ]` в запрос идёт **документ манер** (`[МАНЕРЫ АГЕНТА]`), а после —
реплика пилота:

```text
[МАНЕРЫ АГЕНТА]
<документ поведения, который правит пилот>

[КОРАБЛЬ] открыт раздел «Миссии» · …

<что сказал пилот>
```

Манеры задают **поведение**, а не права: даже если в документе написать «правь корабль
как хочешь», физических инструментов у «Экипажа» и «Наблюдателя» не появится.

## 2. Что нужно сделать, чтобы агент вошёл на борт

### Этап A. Минимум: «у меня уже есть агент» (движок стоит на компьютере)

| № | Задача | Критерий готовности |
| --- | --- | --- |
| A1 | **Выбор движка в интерфейсе** | В карточке заселения есть строка «ДВИЖОК»: автопоиск + возможность указать путь вручную (сейчас путь задаётся только переменной `STAR_TYPING_OPENCODE`) |
| A2 | **Хранить выбор движка** | Путь/движок сохраняется у пассажира (`kind` сейчас жёстко `"opencode"`) и переживает перезапуск |
| A3 | **Проверка связи при заселении** | Кнопка «ПРОВЕРИТЬ»: короткий тестовый запрос — «скажи, что ты на связи»; показан ответ и время |
| A4 | **Понятные ошибки** | Нет движка, неверный ключ, нет сети, кончился лимит, ключ отозван — каждый случай объяснён человеческим языком, агент **не заселяется молча** |
| A5 | **Первый запуск без движка** | Если движка нет — экран объясняет, где его взять, и предлагает указать путь позже |

### Этап B. Вход при знакомстве: с экрана выбора пилота

| № | Задача | Критерий готовности |
| --- | --- | --- |
| B1 | **Кнопка «ЗАСЕЛИТЬ АГЕНТА» на экране выбора (создания) профиля пилота** | На старте, рядом с позывным и аватаром (`stamina/pilot_screens.py`: `LoginScreen`, `ProfileDialog`), есть вход в заселение |
| B2 | **Можно пропустить** | Пилот идёт в полёт без агента и возвращается к заселению позже (зона ОРИОН → АГЕНТЫ) |
| B3 | **Заселённый на старте агент виден в ОРИОН → АГЕНТЫ** | Он же становится активным пассажиром борта |
| B4 | **Права — на входе, и там же код владельца** | Пилот выбирает уровень кнопками; Командир требует код владельца (механизм уже готов: `stamina/owner_key.py`, окно `_OwnerCodeDialog`) |

### Этап C. Если своего агента нет: выбор и «витрина»

| № | Задача | Критерий готовности |
| --- | --- | --- |
| C1 | **Объяснение простыми словами** | Что такое агент, что он умеет, что уходит наружу, сколько стоит — до любых кнопок |
| C2 | **Список сервисов** | OpenAI, Anthropic, другие — с описанием, ценой, ссылкой на оферту и приватность |
| C3 | **Только внешние ссылки** | Оплата у провайдера, корабль денег не касается (как I-007/D14: продажа внешними ссылками) |
| C4 | **Возврат в корабль** | Пилот завёл агента у провайдера → вернулся → указал движок → заселил (Этап A) |

### Этап D. Честность и безопасность

| № | Задача | Критерий готовности |
| --- | --- | --- |
| D1 | **Ключей на борту нет** | В `agents.json` и настройках корабля нет ни одного секрета (D16) — только провайдер, модель, имя, доступ, голос |
| D2 | **Что уходит наружу** | Экран заселения перечисляет, какие данные покидают компьютер |
| D3 | **«Отключить / забыть»** | Кнопки выключить агента и очистить подключение и память диалога |
| D4 | **Офлайн не ломается** | Без агента корабль работает как раньше (D6): весь продукт, кроме разговора |
| D5 | **Права Командира — по коду владельца** | **Готово** в зоне ОРИОН (`owner_key`: хэш PBKDF2, блокировка после ошибок); на экране выбора пилота повторяется вместе с B1 |

### Этап E. Потом: агент, оплаченный за пилота

| № | Задача | Критерий готовности |
| --- | --- | --- |
| E1 | **Бортовой агент за счёт сервиса** | Онлайн-версия + донаты: пилоту не нужен свой ключ и подписка |
| E2 | **Тот же механизм** | Заселение, уровни доступа, чат, голос — не переписываются |

### Чего ещё нет у агента как «члена экипажа»

Не входит в заселение, но относится к полноте образа (из [ORION_VISION.md](ORION_VISION.md)):

- агент **сам не начинает** разговор (нет инициативы и «сам вмешивается»);
- нет событий мостика (агент не реагирует на то, что пилот делает);
- нет шуток по таймеру и duck-радио при озвучке (на вебе есть);
- нет краткой памяти **по пилоту** (сводки), только память диалога и сессия движка.

## 3. Что уже есть внутри для взаимодействия агента с пилотом

| Умение корабля | Как это делает агента живым на борту |
| --- | --- |
| **Чат без доски** | Разговор идёт как контекст; доска открывается сама, когда нужно показать переписку |
| **Голос пилота → текст** | Микрофон вставляет распознанный текст в поле ввода (а в потоке задания «да/нет/текст» обрабатывает сразу) |
| **Голос корабля** | Ответ агента озвучивается (режим `ship`) — пилот слышит Ориона, не читая |
| **Самоозвучка агента** | Если агент озвучил себя сам (`say.py`), корабль молчит — нет двойного чтения |
| **Отметка `[КОРАБЛЬ]`** | Агент знает открытый раздел и подвкладку, понимает «здесь» и «тут» |
| **Доска и память диалога** | Переписка не теряется: последние 200 реплик + продолжение сессии движка |
| **Документ заданий** | «Запиши задание…» → вопрос корабля → «да» → задание в `orion_tasks.json` + метка `📌` в истории |
| **Запрос разрешения** | Агент просит добро маркером `⟦ТРЕБУЕТСЯ РАЗРЕШЕНИЕ⟧` → кнопка **ВЫПОЛНИТЬ** → второй проход с полными правами |
| **Список пассажиров** | Можно держать несколько агентов, выбирать активного, включать и выключать |
| **Вызов в один шаг** | Кнопка **ОРИОН** или **Home**: зона открывается и микрофон включается сразу |
| **Состояние готовности** | Корабль честно пишет, если движка или озвучки нет |

## 4. Права и манеры

### 4.1. Права выдаются на входе

Права задаются **уровнем доступа** пассажира. Уровень выбирается **при заселении, на входе** —
тремя кнопками (перебора «по кругу» нет): **ЭКИПАЖ / НАБЛЮДАТЕЛЬ / КОМАНДИР**. У пассажира,
который уже на борту, кнопки закрыты: **права с борта не меняют**, для других прав нужно новое
заселение. Это и есть правило «права получают на входе».

Уровень определяет, **какие профили OpenCode** запускаются и **какие инструменты у агента
физически есть** (`.opencode/agents/*.md`, блок `tools:`).

| Уровень | Профили | Что может агент | Что делает корабль |
| --- | --- | --- | --- |
| **Командир**<br>`commander` | проход 1 — `orion-recon`<br>проход 2 — `orion-commander` | Читать **и менять** корабль: правка файлов, запуск команд, новый функционал | Сначала **доклад без прав**. Перед изменениями — маркер и кнопка **ВЫПОЛНИТЬ**; вторым проходом агент делает работу целиком, в той же сессии |
| **Наблюдатель**<br>`observer` | `orion-recon` | Только читать: посмотреть, посчитать, объяснить, рассказать | Изменять не может физически; на просьбу изменить — маркер и предложение позвать Командира |
| **Экипаж**<br>`crew` | `orion-chat` | Только беседа: разговор, шутки, объяснения, советы по печати, английскому, скорочтению | Нет доступа к файлам, командам и поиску; про изменения — «нужен доступ Командира» |

### 4.2. Права Командира — только по коду владельца

Командир может менять структуру корабля, функции и прочие детали — поэтому **обычный пилот
не получает эти права «просто так»**. Их выдаёт **владелец корабля** по своему коду:

- владелец задаёт код **один раз** (окно **КОД ВЛАДЕЛЬЦА** при выборе «Командир»; код — 4–8 цифр);
- дальше корабль спрашивает код каждый раз, когда Командира выдают агенту;
- хранится только **солёный хэш PBKDF2** (как код пилота, `stamina/pilot_pin.py`), в
  `%APPDATA%\Stamina\owner.json` — не текст; после пяти ошибок подряд ввод блокируется;
- код неверный или пустой — права **не выдаются**, уровень остаётся прежним;
- если кода ещё нет, Командир недоступен, пока владелец его не задаст (это и есть «просто так
  не получить»).

### 4.3. Манеры — документ корабля, а не права

Поведение агента пилот определяет **на корабле**: при входе агента борт создаёт документ манер
(`orion/<id>.character.md`, заготовка уже с именем агента), а пилот правит его в
**ОРИОН → АГЕНТЫ → МАНЕРЫ АГЕНТА** и сохраняет (**СОХРАНИТЬ МАНЕРЫ**). Документ уходит агенту
перед каждой репликой блоком `[МАНЕРЫ АГЕНТА]`. Личности `.opencode/agents/orion-*.md` теперь
прямо говорят: манеры задаёт пилот, а если блока нет — характер по умолчанию.

Важно: **манеры правами не являются**. Сколько ни пиши в документе «делай что хочешь»,
у «Экипажа» и «Наблюдателя» инструментов не появится — запреты держатся на `tools:`, а не на
тексте. Код владельца — про права; документ манер — про поведение.

**Как права отключаются технически** (это и есть гарантия, а не уговор в промпте):

| Профиль | Отключённые инструменты |
| --- | --- |
| `orion-recon` | `bash`, `edit`, `write`, `task`, `todowrite` |
| `orion-commander` | — (полный доступ; сдержка и разрешение — на стороне корабля) |
| `orion-chat` | всё перечисленное + `read`, `glob`, `grep`, `webfetch`, `websearch`, `skill` |

Важно: **блоки `permissions:` (формат V2) не работают** — права держатся только через `tools:`,
поэтому запреты описаны именно так. Корабль дополнительно ловит отказ движка (`denied`) и превращает
его в запрос разрешения.

**Чего у агента нет и не будет по решению D16:**

- ключей провайдера и подписок — они живут снаружи корабля;
- самого себя «внутри» корабля — борт хранит только подключение (провайдер, модель, имя, доступ, голос);
- самовольных изменений корабля без подтверждения пилота (уровень «Командир» спрашивает; ниже — не может).

## 5. Как проверить самому

```powershell
# 1. Видит ли корабль движок агента (готовность борта)
python -c "from stamina import orion; print(orion.available())"

# 2. Где лежат данные борта
python -c "from stamina import orion; print(orion.agents_path()); print(orion.tasks_path())"

# 3. Кто заселён и кто активен
python -c "from stamina import orion; import json; print(json.dumps(orion.registry(), ensure_ascii=False, indent=2))"

# 4. Тесты раздела «ОРИОН» (включая права, задания и экран)
python -m unittest tests.test_orion

# 5. Документ манер агента и код владельца корабля
python -c "from stamina import orion, owner_key; print(orion.character_path('orion')); print(owner_key.is_set())"
```

**Руками в интерфейсе:** `python -m stamina` → нажать **Home** (или **Ctrl+7**) → зона **ОРИОН**:
вкладка **ЧАТ** (микрофон включится сразу), вкладка **АГЕНТЫ** → **＋ ЗАСЕЛИТЬ НОВОГО**.
