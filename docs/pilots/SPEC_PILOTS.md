# Профили пилотов (несколько пользователей) — спецификация

> Статус: **реализовано в версии 3.4.0** (см. STATUS). План сборки — [CURSOR_TASK_PILOTS.md](CURSOR_TASK_PILOTS.md).
> Касается всего Star Typing: печать и миссии, свой текст («1984»), вкладка «АНГЛИЙСКИЙ», будущий отсек «СКОРОЧТЕНИЕ» (`docs/speedread/`).
> Макеты: `mockups/pilot-select.png`, `mockups/pilot-create.png` (PNG отрисованы на Linux шрифтом DejaVu, в Windows HTML покажут Bahnschrift / Cascadia Mono).

## 1. Зачем и что
За одним ноутбуком занимаются несколько человек. У каждого — **свой пилот**: позывной, эмблема, звание и весь прогресс. Пилоты не видят и не портят прогресс друг друга. Нынешние данные становятся **первым пилотом** без потерь.

## 2. Термины
- **Пилот** — профиль пользователя. **Экипаж** — все пилоты на этом компьютере.
- **Позывной** — короткое имя (обязательно, уникально, 2–16 символов, буквы/цифры/пробел/дефис, хранится как ввели, сравнивается без учёта регистра). **Имя** — необязательно.
- **Эмблема** — аватар: встроенная или своя картинка.
- **Код доступа (PIN)** — необязательный код из 4–8 цифр на пилота; спрашивается при входе (§3.7).
- **Акцент** — цвет рамки эмблемы и карточки из токенов DESIGN: `cyan` (по умолчанию), `amber`, `green`, `red`, `purple`. Остальной интерфейс не перекрашивается.

## 3. Экраны

### 3.1 «ВХОД В КАБИНУ» — выбор пилота (макет `pilot-select.png`)
- Показывается **при запуске**, если пилотов больше одного и включено «Спрашивать при запуске» (по умолчанию ВКЛ при ≥ 2 пилотах). При одном пилоте или выключенной галочке сразу входим последним пилотом.
- Шапка урезана: логотип, «ЭКИПАЖ: N ПИЛОТОВ», часы. Вкладок нет.
- Ряд карточек (`HudPanel`, до 4 в ряд, дальше прокрутка): эмблема в шестиугольнике 110 px цветом акцента, позывной 20 pt (если не помещается в одну строку — переносится на две), имя второй строкой (у первого пилота: «George Orwell / 1984»), значок 🔒 «КОД» в углу карточки, если у пилота задан код доступа, звание `AMBER`, полоса XP до следующего звания, табло: ПЕЧАТЬ (лучшая/последняя скорость зн/мин), «1984» (% своего текста), ENGLISH (слов выучено), ЧТЕНИЕ (скорость сл/мин или «—»), «последний полёт · когда». В углу карточки мелкие ✎ ⇪ ✕.
- Выбранная карточка — рамка `AMBER`, метка «▶ ВЫБРАН», лёгкая янтарная подложка.
- Последняя карточка — «ЗАЧИСЛИТЬ В ЭКИПАЖ» (пунктирная рамка, «+»), под ней «⇩ ИМПОРТ ПИЛОТА».
- Внизу: «► ВОЙТИ В КАБИНУ · <ПОЗЫВНОЙ>» `Enter` (`AMBER`), «✎ ПЕРЕИМЕНОВАТЬ» `F2`, «⇪ ЭКСПОРТ», «✕ УДАЛИТЬ» `Del` (`RED`), справа галочка «СПРАШИВАТЬ ПРИ ЗАПУСКЕ».
- Вход в пилота с кодом открывает окно «КОД ДОСТУПА» (§3.7).
- Клавиши: ← → / Tab — выбор, Enter или двойной клик — вход, Insert — новый пилот, F2, Del, Esc — выход из программы (на старте) или возврат (если открыто из шапки).

### 3.2 «ЗАЧИСЛЕНИЕ В ЭКИПАЖ» — новый пилот (макет `pilot-create.png`)
- **Личное дело**: «Позывной *» (поле-табло, фокус по умолчанию), «Имя», «Акцентный цвет» (5 плашек), «Код доступа» (необязательно: два поля «код» / «повторите код», 4–8 цифр, ввод скрыт точками), «Стартовые настройки»: «Копировать настройки от …» (выпадающий список пилотов или «по умолчанию»). Копируются только настройки, никогда не прогресс.
- **Эмблема пилота**: сетка 16 встроенных эмблем (8 × 2), выбранная — рамка `AMBER`. Ниже «СВОЁ ИЗОБРАЖЕНИЕ»: «⇪ ЗАГРУЗИТЬ ФАЙЛ…», «⟲ СБРОСИТЬ», окно кадрирования (§4.2).
- **Предпросмотр**: карточка как на экране входа и мини-плашка «как в шапке».
- Ошибки — под полем `RED`: «Позывной занят», «Слишком короткий», «Недопустимые символы».
- «✓ СОЗДАТЬ ПИЛОТА» `Enter` → пилот создан, сразу вход. «ОТМЕНА» `Esc`.
- Тот же экран в режиме **«ЛИЧНОЕ ДЕЛО · РЕДАКТИРОВАНИЕ»** — для переименования, смены эмблемы, цвета и кода доступа (кнопка «СОХРАНИТЬ»). Сменить или снять код можно только после ввода текущего кода.

### 3.3 Смена пилота из шапки
- Справа в шапке Star Typing вместо одного звания — плашка пилота: эмблема 30 px + «ПОЗЫВНОЙ ▾» и под ним «★ ЗВАНИЕ · 404 / 700 XP» (как сейчас). Клик — меню: «⇄ СМЕНИТЬ ПИЛОТА», «✎ ЛИЧНОЕ ДЕЛО», «⇪ ЭКСПОРТ ПИЛОТА».
- Горячая клавиша **Ctrl+Shift+P** — экран входа.
- Перед сменой: полёт/чтение ставится на паузу, всё сохраняется (свой текст, английский, скорочтение), затем открывается «ВХОД В КАБИНУ». Выбор другого пилота перезапускает кабину (§6.3).

### 3.4 Удаление
- Только из экрана входа, **не для активного пилота** (сначала войти другим), нельзя удалить последнего пилота.
- Окно подтверждения в стиле отчёта о полёте, рамка `RED`: «СПИСАТЬ ПИЛОТА «КОМЕТА»?», что будет удалено (звание, N заходов, % «1984», N слов английского), поле «Введите позывной для подтверждения», кнопки «✕ СПИСАТЬ» (активна только при совпадении) и «ОТМЕНА».
- Папка пилота не стирается сразу, а переносится в `%APPDATA%\Stamina\backups\deleted\<позывной>-<дата-время>\` (восстановить можно импортом/вручную). Очистка старше 90 дней — кнопкой в настройках, не автоматически.

### 3.5 Экспорт / импорт
- **Экспорт**: файл `<Позывной>_<ГГГГ-ММ-ДД>.stpilot` (zip): `manifest.json` (`format:"stpilot"`, `version`, версия Star Typing, дата, id, позывной, список файлов с SHA-256) + содержимое папки пилота (§5). Выбор места — диалог «Сохранить как», по умолчанию «Документы».
- **Импорт**: выбрать `.stpilot` → проверка манифеста и хэшей → предпросмотр карточки → если позывной занят, предложить «КОМЕТА-2» или переименовать → новый `id` всегда (не перезаписывать существующего). Файлы данных проходят ту же миграцию версий, что и при запуске.
- В архив не попадают логи, кэш переводов, словари и модели (они общие для программы).

### 3.6 Достижения
- Общий список достижений пилота (`achievements.json`): уже существующие из английской вкладки (`english.json → achievements`) + новые по печати («Первая миссия», «Все миссии ряда ★★★», «Свой текст 25/50/100 %»), скорочтению («500 сл/мин», «Шульте 5×5 < 35 с») и общие («Серия 7/30 дней», звания). На экране входа — счётчик «★ 12 / 40» на карточке (позже), полный список — в «БОРТЖУРНАЛЕ».

### 3.7 Код доступа (PIN) — макет `pin-dialog.png`
- **Необязателен**, задаётся для каждого пилота отдельно: 4–8 цифр. Пользователь решил поставить код на первого пилота «George Orwell»: программа попросит задать его один раз при первом запуске после миграции (§7), значение вводит сам пилот.
- **Когда спрашивается**: при входе в пилота с экрана «ВХОД В КАБИНУ», при запуске с `--pilot` / `STAMINA_PILOT` / «последним пилотом» без экрана выбора (тогда окно кода показывается сразу), при экспорте пилота, при смене/снятии кода, перед списанием пилота с кодом. Внутри уже открытой кабины повторно не спрашивается.
- **Окно «КОД ДОСТУПА»** (модальное, `HudPanel` с рамкой `AMBER` поверх затемнённого экрана входа): эмблема и позывной пилота, «ВВЕДИТЕ КОД ДОСТУПА», ряд ячеек-табло (по числу введённых цифр, точки ●, не цифры), цифровая клавиатура 0–9 / ⌫ / ✓ для мыши, ввод с клавиатуры (цифры, Backspace, Enter, Esc). Кнопки «✓ ВОЙТИ» `Enter`, «ОТМЕНА» `Esc`, ссылка «ЗАБЫЛИ КОД?».
- Код, примеры кодов и коды по умолчанию **никогда не попадают в репозиторий** (он публичный): ни в код, ни в тесты (в тестах — случайные коды), ни в документацию.
- **Неверный код**: ячейки мигают `RED`, «КОД НЕВЕРЕН · осталось попыток: 4». После 5 ошибок подряд — блокировка ввода 30 с (дальше 60, 120, … до 15 мин) с обратным отсчётом; счётчик хранится в `profile.json` и сбрасывается после верного входа.
- **Хранение**: только **солёный хэш**, никогда не сам код: `hashlib.pbkdf2_hmac("sha256", code, salt, 200_000)`, соль 16 случайных байт (`secrets.token_bytes`), сравнение `hmac.compare_digest`. В `profile.json`: `"pin":{"algo":"pbkdf2_sha256","iter":200000,"salt":"<hex>","hash":"<hex>","set":"<дата>"}` + `"pin_fail":{"count":0,"until":null}`; в `pilots.json` — только флаг `"locked": true` для значка 🔒. В логи код не пишется, в памяти не хранится дольше проверки.
- **«Забыли код?» — сброс через подтверждение**: окно `RED` «СБРОС КОДА ДОСТУПА · <позывной>»: предупреждение «Код будет удалён, прогресс сохранится», поле «Введите позывной полностью для подтверждения» + галочка «Я владелец этого пилота или имею разрешение», кнопка «СБРОСИТЬ КОД» активна через 10 с после открытия. После сброса — вход в пилота и сразу экран «ЛИЧНОЕ ДЕЛО» с предложением задать новый код (можно пропустить). Сброс пишется в `pilots_audit.log` (дата, пилот, без кода).
- **Честное ограничение**: это защита от случайного входа в чужой профиль в семье, а не шифрование — данные пилота лежат в обычных JSON, и пользователь Windows может прочитать их напрямую. Так и написать в руководстве.
- **Экспорт/импорт**: хэш кода переносится вместе с пилотом (код после импорта тот же). Экспорт пилота с кодом требует ввести код.

## 4. Эмблемы
### 4.1 Встроенные (16)
Шестиугольная рамка (как логотип Star Typing) + символ. Символы: ★ ☄ ✈ ♆ ⚡ ◉ ▲ ♛ ⚓ ☾ ✪ ☢ ✦ ⬡ ♞ ⊕ — каждая со своим цветом по умолчанию из токенов. Рисуются кодом на `Canvas` (многоугольник + текст шрифтом Segoe UI Symbol / DejaVu), картинки не нужны. При выборе эмблемы акцент пилота по умолчанию становится её цветом (можно поменять). Позже — набор PNG «шлемы/корабли» в `stamina/assets/avatars/` (свои рисунки, без чужих лицензий).

### 4.2 Своя картинка
- Форматы: **PNG и GIF** (читает сам tkinter). **JPG/WebP — если установлен Pillow** (необязательная зависимость; без него — подсказка «сохраните как PNG»).
- Автокадрирование: центральный квадрат по меньшей стороне → уменьшение до 256×256 (tk: `copy -from … -subsample`; с Pillow — `ImageOps.fit` с качественным ресемплингом). В окне кадрирования рамку можно сдвинуть мышью и масштабировать колесом.
- Сохраняется как `avatar.png` в папке пилота (256×256), исходник не хранится. Отображение — в шестиугольной маске (углы закрашиваются цветом фона поверх картинки), рамка цветом акцента.
- Ограничение размера файла: 15 МБ; ошибки чтения — сообщение, эмблема не меняется.

## 5. Хранение данных
```
%APPDATA%\Stamina\
  pilots.json                     # реестр экипажа (общий)
  app.json                        # общие настройки окна: geometry, ask_on_start, last_pilot
  pilots\
    p-20261009-7f3a\              # id = "p-" + дата + 4 hex; не меняется при переименовании
      profile.json                # {id, callsign, name, accent, avatar:{kind:"builtin"|"file", glyph}, pin?, pin_fail, created, last_seen}
      avatar.png                  # только для своей картинки
      settings.json               # настройки Star Typing (как сейчас)
      stats.json                  # заходы, клавиши, миссии, XP (как сейчас)
      session.json                # незаконченный свой текст («1984»)
      cargo.txt, cargo_original.txt
      english.json                # SM-2 карточки, известные слова, списки, XP английского, достижения
      speedread.json, speedread\texts\   # отсек «СКОРОЧТЕНИЕ»
      achievements.json
  backups\
    pre-pilots-<дата-время>\      # копия до миграции (§7)
    deleted\…                     # списанные пилоты
  *_error.log                     # логи — общие
```
`pilots.json`:
```json
{"version":1,"last_pilot":"p-20261009-7f3a","ask_on_start":true,
 "pilots":[{"id":"p-20261009-7f3a","callsign":"George Orwell","name":"1984","accent":"cyan","locked":true,"pin_setup_pending":false,
            "avatar":{"kind":"builtin","glyph":"star"},"created":"2026-10-09T18:40:00+03:00","last_seen":"…",
            "summary":{"rank":"Лейтенант","xp":916,"cpm":231,"book_pct":19,"en_known":412,"sr_wpm":452}}]}
```
- `summary` — кэш для экрана входа (обновляется при выходе пилота), чтобы не читать все файлы всех пилотов.
- Общее для всех пилотов (не в профиле): словарь и модели английского (`stamina/english/data`, `models/`), кэш переводов `cache\translations.json`, звуки, тексты-образцы, `app.json`.
- **Что по пилоту, а что общее в настройках**: по пилоту — всё из `settings.json` (звук, громкость, звёзды, клавиатура, зоны, шрифт, язык, переводчик, `cargo_opts`), настройки английского и скорочтения; общее (`app.json`) — `geometry` окна, «спрашивать при запуске», последний пилот.
- Запись всех файлов — атомарно (tmp + replace), как сейчас в `session_storage`.

## 6. Изменения в коде (кратко, подробно — в CURSOR_TASK_PILOTS.md)
### 6.1 Точка выбора папки
Сейчас пути вычисляются при импорте: `session_storage.SESSION_PATH` → `storage.DATA_DIR` → `english/paths.PROGRESS_PATH` и др. Новое: модуль `stamina/pilots.py`, который **до импорта остальных модулей** определяет активного пилота и задаёт папку; `session_storage._session_dir()` возвращает `pilots.active_dir()`. Всё остальное (`DATA_DIR`, `english.json`, `speedread.json`) по-прежнему выводится из неё — изменений по всему коду минимум. Корень `%APPDATA%\Stamina` — `pilots.ROOT_DIR` (для логов, реестра, бэкапов).
### 6.2 Запуск
`main.py` → `run_app()`: миграция (§7) → реестр → если нужно, окно «ВХОД В КАБИНУ» (отдельное лёгкое `Tk`, импортирует только `theme`/`hud`/`pilots`) → `pilots.activate(id)` → обычная кабина. Аргумент командной строки `--pilot <id|позывной>` и переменная `STAMINA_PILOT` — вход без выбора (для ярлыков на каждого пилота).
### 6.3 Смена пилота
Надёжный путь: сохранить всё, закрыть кабину и **перезапустить процесс** `pythonw main.py --pilot <id>` (`subprocess.Popen` + выход). Так все модули получают новые пути без риска смешать данные. Внутрипроцессная смена — не делать.
### 6.4 Шапка
`cockpit.update_rank()` дополнить плашкой пилота (эмблема + позывной ▾), меню, Ctrl+Shift+P. Заголовок окна: «Star Typing — пилот КОМЕТА».

## 7. Миграция существующих данных (обязательно без потерь)
1. При первом запуске новой версии, если нет `pilots.json`, но есть любой из файлов `settings.json, stats.json, session.json, cargo.txt, cargo_original.txt, english.json, speedread.json` (или `translations.json` в корне):
2. **Резервная копия**: весь `%APPDATA%\Stamina` (кроме `backups\`) → `backups\pre-pilots-<ГГГГММДД-ЧЧММСС>\`, проверка: число файлов и SHA-256 совпадают. Если копия не удалась — миграция отменяется, программа работает по-старому и пишет `pilots_error.log`.
3. Создать пилота №1: позывной **«George Orwell»**, имя (вторая строка) **«1984»**, эмблема ★, акцент cyan. Код доступа при миграции **не задаётся** (в коде и в документации нет никакого значения по умолчанию); в `profile.json` ставится флаг `"pin_setup_pending": true`. Позывной, имя и код можно поменять потом в «ЛИЧНОМ ДЕЛЕ».
4. **Скопировать** (не переместить) файлы данных в `pilots\<id>\` побайтно; проверить SHA-256 каждого файла. `geometry` из `settings.json` перенести в `app.json` (в профиле тоже оставить — безвредно).
5. Записать `pilots.json` (атомарно) — это «точка фиксации»: пока его нет, миграция считается незавершённой и повторяется с шага 2.
6. После успешной записи старые файлы в корне **переименовать** в `*.migrated` (не удалять), чтобы старая версия программы не начала писать в них по ошибке. Удаление — вручную позже.
7. **Первый запуск после миграции — задать код**: пока у пилота `pin_setup_pending: true`, сразу после входа показывается окно «ЗАДАЙТЕ КОД ДОСТУПА» (тот же вид, что «КОД ДОСТУПА», §3.7): «новый код» и «повторите код», 4–8 цифр, кнопки «✓ СОХРАНИТЬ КОД» и «ПОЗЖЕ». Сохранение → хэш с солью (§3.7), `locked: true`, флаг снимается. «ПОЗЖЕ» → окно появится при следующем запуске (не чаще раза за запуск), пока код не задан или пилот в «ЛИЧНОМ ДЕЛЕ» явно не выберет «Без кода».
8. Проверка после миграции: свой текст «1984» открывается на той же позиции (`session.json → index`), XP и звание те же, английский — те же числа карточек/известных слов.
- Миграция идемпотентна и покрыта тестами на временной папке (`APPDATA` подменяется).
- Откат: удалить `pilots.json` и `pilots\`, вернуть `*.migrated` → исходные имена (или скопировать из `backups\pre-pilots-…`). Описать в руководстве пилота.

## 8. Совместимость и безопасность
- Формат существующих файлов **не меняется** — только место. Старые версии программы не увидят новых пилотов (это нормально).
- Защита профиля — необязательный код доступа (§3.7): солёный хэш PBKDF2, защита от случайного входа, не шифрование данных.
- Никакие данные пилотов не уходят в репозиторий и в сеть.

## 9. Решения (закрытые вопросы, 2026-10-09)
1. Первый пилот (перенесённый текущий прогресс) — **«George Orwell»**, вторая строка **«1984»**; на карточке показывается в две строки «George Orwell / 1984».
2. **Код доступа входит в объём работ**: необязательный, на каждого пилота, 4–8 цифр, спрашивается при входе, хранится только солёный хэш, «Забыли код?» — сброс через подтверждение (§3.7). Пользователь решил поставить код на первого пилота; программа попросит его задать при первом запуске после миграции (значение в документации и коде не хранится).
3. Ярлыки на рабочем столе на каждого пилота (`--pilot`) — по желанию, не обязательно; при запуске ярлыком код всё равно спрашивается.
