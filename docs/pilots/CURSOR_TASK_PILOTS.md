**Решения пользователя:** первый пилот — «George Orwell» / «1984»; пользователь решил поставить на него код доступа — программа просит задать код один раз при первом запуске после миграции (значение вводит сам пилот, в репозитории его нет); код доступа — в объёме работ (SPEC §3.7). Репозиторий публичный: никаких кодов по умолчанию/примеров в коде, тестах и документах.

**Жёсткие правила:** прогресс «1984», XP/звание, английский — сохранить один в один; перед миграцией — резервная копия; старые файлы не удалять (только `*.migrated`); существующие форматы JSON не менять.

## 3. План
### Шаг 0. Подготовка
- [ ] Резервная копия `D:\My_New_Stamina` и `%APPDATA%\Stamina`; ветка `feature/pilots` (после того как текущая ветка английской вкладки слита).
- [ ] Найти все места, где строятся пути к данным: `rg "APPDATA|DATA_DIR|SESSION_PATH|PROGRESS_PATH|expanduser|\.stamina"`.
- **Готово, когда:** список мест записан в STATUS, программа на ветке запускается как раньше.

### Шаг 1. Реестр и активная папка (`pilots.py`)
- [ ] `ROOT_DIR`, чтение/атомарная запись `pilots.json` и `app.json`, `active_dir()`, `activate(id)`, генерация `id`, проверка позывного.
- [ ] `session_storage._session_dir()` → `pilots.active_dir()`; логи и кэш — в `ROOT_DIR`.
- **Готово, когда:** с подменённой `APPDATA` и двумя пилотами `--pilot A` и `--pilot B` пишут в разные папки; без пилотов поведение прежнее.

### Шаг 2. Миграция (`pilot_migrate.py`) + тесты
- [ ] Пилот №1: позывной «George Orwell», имя «1984», эмблема ★, cyan, кода нет, `pin_setup_pending: true` в `profile.json`.
- [ ] Резервная копия `backups\pre-pilots-…` с проверкой SHA-256; копирование в `pilots\<id>\`; `pilots.json` как точка фиксации; `*.migrated`; `geometry` → `app.json`; лог ошибок; идемпотентность.
- [ ] `tests/test_pilots.py`: чистая установка, обычная миграция, повтор после сбоя на каждом шаге, повторный запуск (ничего не делает).
- **Готово, когда:** тесты зелёные; у пилота «George Orwell» `pin_setup_pending: true` и нет поля `pin`; на **копии** реальных данных ноутбука после миграции `session.json/stats.json/english.json/settings.json` побайтно равны исходным (SHA-256).

### Шаг 3. Порядок запуска (`app.py`)
- [ ] Миграция → (при ≥ 2 пилотах и `ask_on_start`) окно входа → активация → кабина. `--pilot`, `STAMINA_PILOT`.
- **Готово, когда:** ярлык на рабочем столе запускает программу; с одним пилотом окно входа не появляется, «1984» продолжается с той же позиции.

### Шаг 3а. Код доступа (`pilot_pin.py` + окно «КОД ДОСТУПА», макет `pin-dialog.png`)
- [ ] `set_pin(profile, code)`, `verify(profile, code)`, `clear_pin(profile)`: PBKDF2-HMAC-SHA256, 200 000 итераций, соль 16 байт `secrets`, `hmac.compare_digest`; 4–8 цифр.
- [ ] Окно ввода: ячейки-точки, цифровая клавиатура, ввод с клавиатуры, «КОД НЕВЕРЕН · осталось попыток N», блокировка 30 с → 60 → … ≤ 15 мин (счётчик в `profile.json`).
- [ ] Спрашивать при входе с экрана выбора, при `--pilot`/последнем пилоте без экрана выбора, при экспорте, смене/снятии кода, списании.
- [ ] «ЗАБЫЛИ КОД?»: окно сброса (ввод позывного + галочка + задержка 10 с), запись в `pilots_audit.log` без кода, затем «ЛИЧНОЕ ДЕЛО» с предложением задать новый код.
- [ ] Окно «ЗАДАЙТЕ КОД ДОСТУПА» после входа, пока `pin_setup_pending: true`: два поля, «СОХРАНИТЬ КОД» → хэш, `locked: true`, флаг снят; «ПОЗЖЕ» → спросить при следующем запуске.
- [ ] Тесты (коды генерируются случайно в тесте, без фиксированных значений): верный/неверный код, разные соли для одинаковых кодов, блокировка, сброс, введённый код не встречается открытым текстом ни в одном файле `%APPDATA%\Stamina`.
- **Готово, когда:** при первом запуске после миграции «George Orwell» просят задать код; после этого вход требует этот код; после 5 ошибок — отсчёт блокировки; сброс через подтверждение работает и прогресс не теряется.

### Шаг 4. Эмблемы (`avatars.py`)
- [ ] 16 встроенных (Canvas: шестиугольник + символ, цвета токенов); загрузка PNG/GIF, JPG при наличии Pillow; центральный кроп 256×256; маска-шестиугольник; ограничение 15 МБ.
- **Готово, когда:** эмблема одинаково выглядит в размерах 30/58/110/120 px; своя картинка 4000×3000 PNG кадрируется и сохраняется как `avatar.png` 256×256.

### Шаг 5. «ВХОД В КАБИНУ» (по макету `pilot-select.png`)
- [ ] Карточки с `summary`, выбор ← →/Enter/двойной клик, «ЗАЧИСЛИТЬ В ЭКИПАЖ», импорт, переименовать (F2), экспорт, удалить (Del), галочка «Спрашивать при запуске».
- **Готово, когда:** всё работает с клавиатуры и мышью, цифры на карточках совпадают с данными пилотов.

### Шаг 6. «ЗАЧИСЛЕНИЕ В ЭКИПАЖ» / «ЛИЧНОЕ ДЕЛО» (по макету `pilot-create.png`)
- [ ] Позывной/имя/акцент, необязательный код доступа (два поля), сетка эмблем, своя картинка с кадрированием, предпросмотр, «копировать настройки от…», валидация, режим редактирования.
- **Готово, когда:** новый пилот появляется сразу как «Кадет · 0 XP», у него пустая статистика, пустой английский и нет своего текста; у старого пилота ничего не изменилось.

### Шаг 7. Шапка и смена пилота
- [ ] Плашка пилота в шапке, меню, Ctrl+Shift+P, заголовок окна; сохранение всего и перезапуск процесса с `--pilot`.

- **Готово, когда:** экспорт → удаление → импорт возвращает пилота с тем же прогрессом (сравнение SHA-256 файлов данных).
